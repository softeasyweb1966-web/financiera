4. Situacion de los datos
-------------------------
La informacion historica mas fuerte esta en el backup de PostgreSQL.

La SQLite actual tiene principalmente:
- avances nuevos del modulo comercial

- atenciones

- pagos de seguimiento

Recomendacion:

- Ejecutar las migraciones actuales del proyecto
- Luego migrar automaticamente desde SQLite las tablas que sigan faltando en PostgreSQL
- Y solo volver a digitar manualmente aquello que no convenga conservar como prueba


5. Conexion a PostgreSQL
------------------------
Ejemplo para PostgreSQL local:

postgresql+psycopg2://postgres:TU_PASSWORD@localhost:5432/prevent

Ejemplo para nube:

postgresql+psycopg2://usuario:password@host:puerto/base?sslmode=require


6. Variable de entorno
----------------------
Antes de arrancar la app, definir DATABASE_URL.

Ejemplo en PowerShell:

$env:DATABASE_URL = "postgresql+psycopg2://postgres:TU_PASSWORD@localhost:5432/prevent"


7. Pasos para dejar PREVENT en PostgreSQL
-----------------------------------------
Paso 1:
Crear o escoger la base PostgreSQL destino.

Paso 2:
Definir DATABASE_URL apuntando a esa base.

Paso 3:
Ejecutar migraciones del proyecto:

cmd /c .venv\Scripts\python.exe -m flask --app .\run.py db upgrade

Paso 4:
Restaurar el backup logico solido:

.\.venv\Scripts\python.exe .\restore_postgres_logical.py --backup-dir .\backups\pg_logical_backup_20260325_031434

Si la base destino ya tiene datos y se quiere reemplazar:

.\.venv\Scripts\python.exe .\restore_postgres_logical.py --backup-dir .\backups\pg_logical_backup_20260325_031434 --clean-target

Paso 4.1:
Migrar desde SQLite lo que siga faltando en PostgreSQL y cuya tabla destino este vacia:

.\.venv\Scripts\python.exe .\migrar_sqlite_restante_a_postgres.py

Paso 5:
Arrancar la aplicacion:

cmd /c .venv\Scripts\python.exe .\run.py

Paso 6:
Ver inventario de datos en PostgreSQL:

.\.venv\Scripts\python.exe .\ver_postgres_resumen.py

Ese script deja un archivo:

postgres_resumen.json

8. Script creado para restauracion
----------------------------------
Se creo este archivo para restaurar el backup logico hacia PostgreSQL:

restore_postgres_logical.py

Ese script:
- toma un backup logico en JSON/CSV
- revisa tablas compatibles
- inserta los datos en PostgreSQL
- reinicia secuencias
- genera reporte de restauracion

Tambien se creo este archivo para migrar a PostgreSQL las tablas que hoy solo existan en SQLite
o que sigan vacias en el destino:

migrar_sqlite_restante_a_postgres.py


9. Limitacion actual encontrada
-------------------------------
En este equipo hay un servidor local PostgreSQL 16 instalado y corriendo.
Pero la conexion local con el usuario postgres exige password.

Por eso, para terminar la migracion real, hace falta una de estas dos cosas:
- la DATABASE_URL completa de la base destino
- o la password del usuario postgres local
